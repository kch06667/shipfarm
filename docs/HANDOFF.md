# 다음 프로젝트 인수인계

작성 기준: 2026-10-30, 시안 05 / package version 0.5.0.

## 사용자 목표와 작업 원칙

- 옛 **네이버 웹게임 ‘쉽팜 인 슈가랜드’의 느낌과 콘텐츠를 최대한 살리는 것**이 목표다. 혼자 즐기거나 가족끼리 공유할 용도다.
- 사용자는 현재 시안 방향을 받아들였으며, 양의 자율 이동·모션, 더 풍성한 맵, 아기양부터 시작하는 튜토리얼, 지속적인 완성도 개선을 요청했다.
- 최신 선호: **못 챙긴 작물은 썩어야 한다.** 원작의 관리 부담을 편의성 명목으로 없애지 않는다. 사용자가 매번 자료를 제공하기를 기다리지 말고 공개 원작 리뷰·공략을 직접 조사해 구현한다. `docs/original-game-research.md`를 먼저 확인할 것.
- 메타랜드의 NFT·지갑·토큰·레이싱 시스템은 제외한다. 메타랜드 공개 도감은 성체 외형 참고 자료로만 이용했다.
- 현재 결과는 **원작 완전 복원본이 아니다**. 확인된 원작 정보와 새로 만든 규칙·대사·그래픽을 계속 구분해야 한다. 원작 APK/OBB나 서버 로직을 확보한 상태가 아니다.
- 사소한 구현 선택은 자율적으로 진행하되, 기존 목장 데이터를 보존한다. 초기화·복원은 게임 내 확인 절차를 유지한다.

## 시작할 때

저장소는 `kch06667/shipfarm`, 현재 작업 폴더는 `/workspace/shipfarm`이다. 다른 환경에서는 경로가 달라질 수 있다. 시안 05는 `5508c80`으로 GitHub `main`에 반영했다. 이후에도 사용자가 기능 완성·검증 단위의 커밋·push를 승인했다. 새 환경에서는 원격 `main`과 로컬 작업 상태를 확인하고 이어간다. 저장소 밖 연구 자료와 사용자 영상은 별도로 옮겨야 한다.

1. `README.md`, 이 문서, `docs/design.md`의 시안 05 절을 읽는다.
2. `git status`를 확인하고 기존 변경을 보존한다.
3. `npm start`로 실행한 뒤 `http://127.0.0.1:8000`을 연다.
4. 테스트 도구가 없으면 `npm ci` 및 `npx playwright install chromium`을 실행한다.
5. 변경 후 `npm run build`, 영향에 맞는 브라우저 검사, 필요할 때 `npm test`를 실행한다.

게임 실행·빌드 자체는 표준 Node 모듈만 쓴다. Node 20 이상 권장. Playwright는 개발 검증에만 필요하다. `CHROMIUM_PATH` → `/usr/bin/chromium` → Playwright Chromium 순서로 브라우저를 선택한다.

## 남은 작업 — 권장 우선순위

아래는 다음 개발의 제안 목록이며, 전부 이미 구현됐거나 원작 규칙이 확정됐다는 뜻이 아니다.

### 1. 기존 버전의 플레이 완성도와 데이터 안정성

- [ ] 새 목장에서 치트 없이 30~60분 플레이하며 먹이·코인·경험치 흐름을 기록한다. 레벨 10/30/70까지의 소요 시간과 반복 노동량을 점검한다.
- [x] 목장 아래 상태별 다음 행동 안내: 수확·아기양·배고픔·청결·털·판매와 해금 이야기를 연결했다. 앨범·장기 목표 안내는 추가 개선 여지가 있다.
- [x] 긴 작물로 모든 밭이 찬 경우 확인 후 비우거나 1분 작물로 바꾸기. 먹이·코인 0에서도 농사 재개를 검사했다.
- [x] 첫 일반 양털 수확 시 창고/판매 안내 추가. 재접속에도 유지되며 첫 판매를 마치면 사라진다.
- [ ] 풀밭의 집·연못·밭·장식과 양의 실제 겹침을 확인하고 이동 경로를 개선한다. 현재는 제한된 좌표와 양끼리의 밀어내기이며 완전한 장애물 경로 탐색이 아니다.
- [ ] 먹이 이동 중 탭 전환·재접속·쉼터 교대, 여러 아기양 동시 성장, 긴 오프라인 경과를 추가 점검한다.
- [ ] 실제 Android/iOS에서 터치, 가로 목장 스크롤, 긴 대화상자, 키보드 등장, 백업 파일 다운로드/복원을 확인한다.
- [ ] 여러 브라우저 탭이 같은 목장을 덮어쓰는 문제와 손상된 localStorage 복구 방식을 설계한다. 파일 가져오기 검사는 있지만 직접 저장값 전체의 손상 복구는 더 보강할 여지가 있다.
- [x] 이웃 화면의 한국 시간 자정 갱신과 탭 복귀 시 갱신. 날짜 역행·중복 보상 방지 및 키보드 포커스 유지 검사 완료. 서버 시간 검증은 현재 없다.

완료 기준: 기존 저장을 유지하면서 기본 반복 플레이가 막히지 않고, 실제 기기에서도 돌봄·구매·복원이 가능할 것.

### 2. 양 모션과 목장 그래픽

- [ ] 정지 PNG에 적용한 몸 흔들림·다리 모션을 개선한다. 종별 크기, 귀·꼬리, 잠·먹기·씻기·털 깎기의 차이를 준다.
- [ ] 아기양은 현재 공통 SVG다. 종별 또는 색상별 아기 외형을 설계하되 원본과 창작을 표시한다.
- [ ] 인형양이 자면서도 눈을 감지 않는 등 사용자가 제공한 특징을 반영한다.
- [ ] 장식 종류와 배치 가능 범위를 늘린다. 이동 충돌·깊이 순서·모바일 조작까지 함께 설계한다.
- [ ] 필요하면 실제 풀밭/밭 확장을 구현한다. 현재 ‘확장’은 **쉼터 자리 확장**이고 풀밭 6마리·밭 6칸은 고정이다.
- [ ] 선택형 효과음·배경음을 검토한다. 구현 시 기본 자동 재생을 피하고 음량·끄기 설정을 제공한다.

### 3. 원작 콘텐츠 추가 복원

- [ ] 초밥양: 연어초밥·중뱃살초밥·계란말이·락교·참치초밥·유부초밥·새우·연어알 등 사용자 캡처를 목록화하고 대응 이미지를 확보한다. 해금 레벨 36은 미확정이다.
- [ ] 천사양 1/2를 구분한다. 현재 Spring Rose Cherub 한 종류를 ‘천사양’으로 표시한다. ‘메에메에엘의 시험’과 ‘선과 악 7/7’의 실제 연결을 다시 확인한다.
- [ ] 미스테리 양상자: 나무·은·금 상자 및 ‘잃어버린 전설’ 자료를 확보한다. 보상 확률/내용을 임의로 원작 값이라 하지 않는다.
- [ ] 얼짱양(레벨 45), 차도양(62), 공모전 양(프린세스램·차도양 흑/백·인형양·울프램 등)의 분류·외형을 재확인한다.
- [ ] 이벤트 양: 짜장·계란후라이·복숭아슈·달토끼·오로라·팬지·큐피트·감슈·잭오램턴 등. 이름만으로 유사 외형을 잘못 대응하지 않는다.
- [ ] 기본/슈크림/플레임의 남은 무늬·색상, 교역양 캡처를 정리한다. 교역양 이미지의 최저·최고 가격은 일반 상점 가격과 구분한다.
- [ ] 보닛·공주·왕자·블레이징 등 모바일 전용 종을 웹 원작 종과 분리한다. 추가한다면 확장 콘텐츠로 표시한다.
- [ ] 원작 퀘스트 순서·NPC·대사·보상·성장/먹이 주기 자료를 더 수집한다. 현재 대사·목표·생활 공식은 대부분 새 설계다.
- [x] 작물은 성숙 후 지속시간이 지나면 썩는다. 재배보다 짧은 지속시간을 가진 원작 작물 표로 해석 근거를 확보했고, 오프라인·이전 저장·튜토리얼에도 적용한다. 부패한 작물은 쭉정이 정리만 가능하다.
- [x] 2011년 리뷰의 상호작용 장식인 스프링 쉽을 구현했다. 자율 방문·클릭 방문·새 놀이 모션이며 원본 애니메이션은 아니다.

완료 기준: 각 새 콘텐츠에 출처·확실성·임시 설정을 기록하고, 입양/성장/돌봄/양털/쉼터/저장까지 연결할 것. 도감에 이미지 카드만 늘리고 플레이 가능하다고 보고하지 말 것.

### 4. 장기 진행과 가족 공유

- [ ] 해금 이야기·업적·반복 부탁의 종류를 늘리고 장기 목표를 만든다. 반복 보상 악용과 자원 차감도 검사한다.
- [ ] 가족 공유 형태를 결정한다: 각자 독립 목장, 기기 하나의 여러 프로필, 파일 교환, 서버 기반 공동 목장은 서로 다르다.
- [ ] 현재는 JSON 파일 전달만 가능하다. 로그인·클라우드 저장·실시간 공동 편집은 없다.
- [ ] 서버를 추가한다면 저장 충돌·백업·접근 제한·날짜/보상 검증을 함께 설계한다. 가족용 범위를 넘는 공개 서비스로 임의 확장하지 않는다.
- [ ] 실제 교배/교역은 원작 규칙 자료와 사용자 우선순위를 보고 결정한다. 현재 미구현이다.

## 코드와 저장을 수정할 때 주의점

- 수정 원본: `src/game.js`, `src/crop-life.js`, `src/farm-toys.js`, `src/food-pantry.js`, `src/play-guide.js`, `src/style.css`, `src/shell.html`, `src/assets.json`. 빌더가 모두 단일 HTML에 내장한다.
- 작물은 `ready + cropFreshSeconds[crop]`에 부패하며 `spoiled: true`를 기록해 시간 역행에 되살아나지 않게 한다. `stats.clear`는 쭉정이 정리 횟수다. 모두 선택적 필드여서 이전 저장에도 대응한다. 작물 경과에는 양의 2시간 오프라인 상한을 적용하지 않는다.
- 생성 결과: `index.html`. 직접 수정하면 다음 빌드에 사라진다.
- 빌더: `scripts/build.cjs`. 로컬 실행기: `scripts/serve.cjs`.
- 이미지 31개는 data URL로 내장한다. 외부 API·추적·폰트 요청 없이 동작한다.
- 저장 키는 **`shipfarm-concept-v1`**, 현재 저장 버전은 **2**다. 패키지 버전 0.5.0과 다르다. 저장 키를 바꿔 기존 목장을 잃지 않도록 한다.
- `fresh`, `migrateState`, `ensureProgression`, `ensureHomestead`, `validBackup`, `validateHomestead`가 저장 생성·이관·검사를 담당한다.
- 양 종류는 숫자 인덱스를 저장한다. 기존 `breeds` 순서를 변경하지 말고 뒤에 추가하거나 명시적 마이그레이션을 만든다. 색상 `variant`도 인덱스다.
- 양 이동은 `uid`로 식별한다. 풀밭/쉼터 배열 인덱스를 영구 ID로 사용하지 않는다.
- 종 추가 시 그림뿐 아니라 `woolPrices`, `woolStock` 초기화, 해금 조건, 백업 검증, 이야기 연결을 함께 확인한다.
- 기존 이야기 함수는 장 수 **3**을 전제로 한다. ‘선과 악 7/7’ 같은 7장 이야기를 붙일 때 진행 UI·완료 판정·백업 검사까지 일반화해야 한다.
- 먹이 저장: 선택 필드 `foodStock`(8종), 양의 `foodWish`, `stats.favorite`를 추가했다. `food`는 전체 수량이며 종류별 합과의 차이는 이전 저장의 혼합 먹이다. 수확은 `receiveCropFood`, 일반 납품은 `spendAnyFood`를 사용해 합계와 종류별 재고를 함께 갱신한다. 직접 합계만 변경하지 않는다. 백업은 종류별 합계 초과를 거절한다.
- 먹이 요청은 캬라멜팝콘부터 정해진 순서로 바뀐다. 5개 소비·포만감 25·털 25, 요청 일치 시 추가 털 10·경험치 3은 시안 규칙이다. 튜토리얼 보상은 기존 그대로이며 실제 원작 공식은 추가 조사 대상이다.
- 생활 주기: 포만감 40초당 1, 청결 90초당 1, 털 8초당 1. 포만감 15 이하/청결 20 이하일 때 자연 털 성장 중단. 모두 시안용이다.
- 테스트의 진행 데이터 주입은 검증용이다. 시작 목장을 고레벨/많은 코인으로 바꾸지 않는다.

## 검증 상태와 한계

최신 구현에서 `npm test`의 열 개 시나리오가 모두 통과했다.

| `tests/variants-smoke.cjs` | 색상 구매→성장→쉼터→저장, 새 종 이동, 풍경, 모바일 색상 창 |

추가로 로컬 실행기 응답, 외부 요청 0건, 네트워크 오프라인 상태의 내장 이미지 31개 디코딩·이름 짓기를 확인했다. 관리형 Chromium의 `file://` 탐색은 정책으로 차단돼 직접 파일 실행은 이 환경에서 검증하지 못했다. 로컬 HTTP 실행을 권장한다. 실제 휴대폰·수 주 장기 플레이는 미검증이다.

## 원작 자료와 이동할 파일

프로젝트로 옮길 최소 범위는 **`/workspace/shipfarm` 폴더 전체**다. `node_modules`는 필요 없으며 `npm ci`로 다시 설치한다. 배포용 단독 실행 파일은 `index.html`이다.

추가 연구 자료는 저장소 밖에 있으므로 필요한 경우 별도로 옮긴다.

- `/workspace/sheepfarm-research/catalog.md`, `sheep.csv`, `crops.csv`
- `/workspace/sheepfarm-research/web-wiki-reference.md`
- `/workspace/sheepfarm-research/metaland/sheep-index.csv`: 공개 도감 약 194개 이름/이미지 URL. 전부 원작 웹판 양이라는 뜻은 아니다.
- `/workspace/attachments/`의 사용자가 업로드한 쉽팜 for Kakao MP4: 아기양/성장/농사 흐름 참고. **모바일 영상이므로 웹판 고증과 구분**한다.
- 대화 속 사용자 상점 캡처: 자동으로 새 프로젝트에 전달되지 않을 수 있다. 원본 캡처를 새 프로젝트에도 첨부하는 편이 좋다.

핵심 외부 출처:

- 웹판 양 상점: https://blog.naver.com/yoakaori/150132026646
- 옛 웹판 위키 보존본: https://github.com/forkwikiman/enha/blob/master/mirror/쉽팜%20인%20슈가랜드.md
- 현재 공개 도감: https://guide.sheepfarm.io/guide/gameplay/sheep
- 현재 사이트: https://sheepfarm.io/

현재 사용한 이미지의 정확한 URL은 `docs/image-sources.csv`, 작물 수치는 `docs/crops-reference.csv`에 있다. 공개 이미지 확보와 사용 허락 확보는 다른 문제이며, 현재는 개인 시안 외형 참고로 사용한 상태다.
